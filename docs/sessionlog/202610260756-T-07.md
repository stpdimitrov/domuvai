## T-07 · 2026-10-26 · tooling — one slice per fresh session, enforced by hooks

**Did** — Why: the WEB-28 session was a long fork (it began in another project), claimed a slice anyway and paid for its whole context on every call; "one slice per session" was only text. `.claude/hooks/claim-gate.sh` (a bash fast path, so every other Bash call costs nothing) + `claim_gate.py`, wired in `.claude/settings.json`: **PreToolUse(Bash)** refuses a claim with exit 2 when this session already claimed or has a claim in flight, when one command claims twice (a marker `.claude/state/claims/<session_id>`, gitignored) or when its transcript is past **1.2 MB**, and prints the §7.5 boot prompt for a fresh session with the lane filled in; the marker is written only when the claim is allowed. **PostToolUse(Bash)** records the claim issue from lanes.py's own "yours, as #n"; a claim that did not take (lane held, lost race) has its marker removed, so the session may pick another lane as §2 says (a marker with no issue older than 120 s counts as not taken). A claim is an invocation in any command segment — `bash -c`, env prefixes, `time`, `then`, flags before the lane — but not one whose segment starts with `echo`/`grep`/`git`/… (showing the words). **Stop** — once that issue is closed (`gh issue view`, at most once a minute), a one-line `systemMessage`, said once: end the session, start the successor; never blocks, exits from bash when there is no marker. `tools/test_hooks.sh` — fake hook stdin, a stubbed `gh`; gate 12/12 of `tools/gates.sh`. CLAUDE.md and zues-slice §2: "Claim only in a session whose first act was the boot", naming the hook.

**The limit** — measured, not guessed: the transcript offset of the first `lanes.py claim` in every local session transcript. Fresh boots claimed at 626k, 728k, 747k, 747k, 790k and 917k bytes (≈430k of a fresh transcript is the fixed tool and skill listing); the WEB-28 fork at 1593k; a long multi-slice session at 4966k. 1.2 MB = the largest fresh boot + ~30%. It is per-machine (the listing grows with connectors): override with `ZUES_CLAIM_MAX_BYTES`.
