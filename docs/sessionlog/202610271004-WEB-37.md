## WEB-37 · 2026-10-27 · web — the import's own page, its commit and its revert

**Did** — the intake wizard's last step, mode BOTH. A new page, `/entrance/intake/<id>?entrance=…`, is rendered from `GET /api/intake/imports/{id}`: the status in words with its code, the rows, the differing bills, the violations, the sheet's SHA-256, and `commitBlockedBy` / `revertBlockedBy` when the API gives them. "Прочети отново" is a link to the same page, so a commit or revert that settles after its answer is read again on request. Nothing polls. The page has a no-script revert form, and the reason is required. It asks `POST /api/intake/imports/{id}/revert` and shows REVERTING, or the API's refusal with the reason kept. In the wizard, the recorded import's id now links to that page. "Приеми внасянето" sends the same sheet, mapping and tariff to `POST /api/intake/imports/{id}/commit`, because the API checks the sheet's hash against the record and runs the dry-run again. The commit answer shows COMMITTING, the units created and changed, the manual entries for a person to record by declaration (never adopted), and the link. No button is hidden by status: whether an import may commit or revert is the API's to say (409, in its words). Who committed or reverted is the sign-in's party (G-1), so no body names an actor. The status words live in `intake/status.ts`.

**Rules covered** — PM-SEC-001 (the API decides who reads, commits and reverts; G-1) · PM-FEE-014 (whether the import still reproduces, and may commit, is the API's).
