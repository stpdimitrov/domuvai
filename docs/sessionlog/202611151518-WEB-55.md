## WEB-55 · 2026-11-15 · web — a vote sent without signal waits on the device as "изпраща се" (#476, closes #455)

**Did** — `web/lib/voteQueue.ts`: the first offline queue in the web client, pure over a handed-in shelf (localStorage). The console's `VoteForm`, once hydrated, keeps a vote on the device under the key its form minted when the browser is offline, the send gets no answer, or the API answers 5xx / 401 / 408 / 429. It shows that vote as "изпраща се" and mints a new key for the form. The queue resends on page load and on the `online` event, under the vote's own key, through the new server action `resendVote`, which makes the same `postVote` call as `castVote` but returns an outcome, not a redirect. A 2xx takes the vote off the queue and refreshes the page, so the API's rows show it recorded. Any other 4xx takes it off and shows the refusal. Without a script the form posts to `castVote` as before (`castVote` now also marks a lost answer `unsettled`). Only the login (party id) that queued a vote sees or resends it. A login tied to no party does not queue.

**Rules covered** — PM-SYS-014.
