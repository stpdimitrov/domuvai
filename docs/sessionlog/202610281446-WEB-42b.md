## WEB-42b · 2026-10-28 · web — a committed disbursement paid or cancelled

**Did** — mode BOTH. Each committed, unpaid disbursement on `/entrance/fund/disbursements` now carries a pay form and a cancel form. Pay records the date the fund's bank paid it (defaulting to today in Sofia, `sofiaToday()`, as a field default only: the API decides whether the date is valid) via `POST …/fund/disbursements/{id}/pay` ← `{paidOn, paidBy}`. Cancel withdraws it with a reason (refused on the web before any call when empty) via `…/cancel` ← `{cancelledBy, reason}`. The signatory is never a field: both actions read `GET /api/identity/me` on the write (`myParty`) and send that `partyId`. Each form's Idempotency-Key is minted once on the page; a refusal re-mints it, a lost answer or a 5xx keeps it (`settled`). A refusal is shown in the API's words, the form kept. The platform moves no money (ADR-007 is Proposed; nothing touches `rail`). This is WEB-42's pay/cancel half, re-applied from `WEB-42-full-with-pay-cancel.diff` onto main: `payOf`/`cancelOf` in `web/lib/disbursement.ts`, `PayCancelForms.tsx` (a new file beside `SignOffForm.tsx`, which is untouched), `pay`/`cancel` in `actions.ts`, the two forms and the `paid`/`cancelled` done-words on the page.

**Small fix, outside the claimed rules** — WEB-39's `payments/actions.ts` minted a new Idempotency-Key after a 5xx, so a resend of a write the API may have recorded could be recorded twice. It now keeps the key on a 5xx, as the disbursement forms do (one condition, `answer.response.status < 500`). Not unit-tested: the action is a server action with no pure seam, and the e2e does not provoke a 5xx.
