## WEB-44 · 2026-10-29 · web — the Book of the Condominium read, and who read it

**Did** — `/entrance/book` (sidebar „Книга на етажната собственост“). The page reads nothing of the book: it renders one form, a date and a free-text purpose, with two buttons — „Прочети книгата“ and „Кой е чел книгата“. Each is one server action (`book/actions.ts`) that refuses an empty purpose before any call (`purposeOf`) and otherwise makes one GET carrying the purpose typed: the book as of the date, or its access log. A browser POST, so the purpose is in no page URL and a reload reads nothing; the API takes it as a query parameter. The book is shown as served: each unit's designation, built area, ideal parts, parties, household count, non-use ranges, and whether the unit and the book are complete (`completeness`: complete only where the API says `true`). A party is drawn only through `partyLine`, which takes name, role and share by name. The log is shown oldest first as served, each entry's time in Sofia's time. A refusal (403, 400, 401) is shown in the API's words through `refusal.ts`.

**Rules covered** — PM-BOOK-001, PM-BOOK-002, PM-BOOK-006, PM-BOOK-007, PM-BOOK-011, PM-SEC-001.

**Tests added** — `web/lib/book.test.ts`, 7 tests named by rule ID: no purpose means no call, and both GETs carry the purpose; the page and the form call nothing; a party with extra fields (ЕГН, address) shows name, role and share only; the page code reads no party field but through `partyLine` and names no ЕГН or address; a 403 is shown in the API's words with its rule; complete only on `true`; Sofia time. E2e `book_screen`: the page is the form alone; a read with no purpose is refused by the page and, signed in, adds no BOOK_READ to the API's log. Signed in (CI, the board): the seeded book is shown as the API serves it for the same purpose (every unit, every party line, the book's flag), the log read through the form lists that purpose, and the API holds two SERVED reads for it (the page's and the check's). With no sign-in (the API open): the API's 403 is shown in its words. The book's two GETs are in CALLS (skipped with no token, like `/me`). The no-sign-in branch is run locally against the open API on :8080, with the web on :3100: ok. A mutant (`purposeOf` always passes) makes it fail, then the code was restored. CI covers only the signed-in branch.
