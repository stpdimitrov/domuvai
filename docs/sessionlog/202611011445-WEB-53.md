## WEB-53 · 2026-11-01 · web — the payment form offers the unit's open debts (the web half of #332, claim #423)

**Did** — on `/entrance/payments` the typed debt date is a pick list. As the unit or the payment's value date changes, the form asks `GET /api/money/units/{unitId}/open-debts?asOf=<value date>` through a server action (`offers.ts`) and lists each debt with its date, due day and what is outstanding. Unchosen is the default: oldest debt first, no `designatedDebtDate` sent. A choice is kept only while the list now offered still includes it (`designationOf`), so one made for another unit or date is never carried over. A refused or failed read, or a unit with nothing posted, offers nothing and says so in the form; the payment is still recorded oldest first. `RecordPaymentRequest`, `payment.ts` and the action that records are unchanged. `tools/check_e2e.py` lists the new call in `CALLS`, validated against the contract on the seeded unit.

**Rules covered** — PM-DEBT-008, PM-SEC-002.

**Tests added** — `lib/openDebts.test.ts`, seven: PM-DEBT-008 an offered debt shows its date, due day and outstanding amount; nothing chosen sends no date; a debt chosen is the one designated; a choice the list no longer offers is dropped; the list is asked for only once a unit and a date are chosen; an answer to an earlier unit or date is not the list now (`offerFor`). PM-SEC-002 a read refused or not yet answered offers nothing — the web decides nothing; the enforcement the rule's Acceptance asks for is the API's, tested by `MoneyAccessIT` (DEBTS-01).

**Mutants** — two, both killed: a choice kept whether or not offered; a refused read's list consulted as if it were a list.

**Not run here** — `tools/check_e2e.py` (needs the API over Postgres; CI runs it) and the form in a browser. `web` type-checks, its 125 tests pass, `next build` passes, `tools/gates.sh` is green. `tools/check.sh web` has no web lane (#342).

**Review** — `zues-reviewer`, fresh context: none blocking; four minors. Taken: the button is held while the list is read (once the script has loaded), so a kept choice is never sent as none; the stale-answer decision moved into `offerFor` and tested; the PM-SEC-002 test says where the enforcement is. Not taken: a designation kept across a refusal when the script is off, or a date input in `<noscript>` — the contract changes only how the date is chosen, and a refusal now needs a debt that closed since the list was read.

**Decisions** — none beyond the contract. Two consequences worth knowing: with no script the form has no way to name a debt (the list is read by script) and the payment goes oldest first; the e2e's no-script post of `designated` is unchanged and still reaches the API's own refusal. The new words avoid the phrases `check_e2e.py` searches for on refused pages: the "unread" sentence only appears after a read the page makes in a browser, never in the server's first render.
