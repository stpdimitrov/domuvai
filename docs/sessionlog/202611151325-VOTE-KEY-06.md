## VOTE-KEY-06 · 2026-11-15 · assembly (+ web) — the item close, the absentee merge and the protocol posting take an Idempotency-Key (#472, closes #461)

**Did** — `POST …/decision`, `…/absentee-merge` and `…/protocol-posting` each require an `Idempotency-Key` (a missing header is a 400; a blank key is a 400 after the policy check, so a caller who may not act still learns only the 403). `DecisionService.close`, `AbsenteeMergeService.merge` and `ProtocolPostingService.record` decide the key through `VoteRequestKeys.decide` straight after the assembly's lock. A new key keeps the key and the act in one transaction, and the row it makes names the key (`request_key_id` on `decision`, `merged_decision`, `protocol_posting`). The same key with the same request writes nothing and answers 201 with what the first one made, even though the item is now closed, merged or entered. The same key for anything else is a 409 (the existing `IllegalStateException` handler takes `IdempotencyKeyReused`). A new key for an act already done is the 409 it was. An act refused for its own reasons (day 7 not over, a day outside the sitting's) rolls the key back with it, so the same form can be sent again once it would be accepted. `vote_request_key` is widened by three operations (`CLOSE_ITEM`, `MERGE_ABSENTEE`, `POST_PROTOCOL`) in a new migration. Each stored time is truncated to the column's microseconds, so a replay reads the instant the first answer did. The three controllers gained a 400 handler for a new `BlankIdempotencyKey` only (it extends `IllegalArgumentException`), so no other bad argument on these paths, `tally`'s or `standing`'s `require` included, changes the status it had. The three console forms mint a key per form, kept when the answer is lost or the API answers 5xx and renewed after a refusal. `openapi.json`, the web client, `check_e2e.py` and the Swagger catalogue are regenerated or updated.

**Rules covered** — PM-SYS-014 (a form sent twice closes one item, merges once, enters one posting). PM-VOTE-016, PM-VOTE-011, PM-VOTE-013, PM-GA-017, PM-GA-023 and PM-SEC-001 are unchanged: no tally, standing, window or who-may-act moved.
