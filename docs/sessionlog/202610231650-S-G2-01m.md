## S-G2-01m · 2026-10-23 · assembly — the persistence tests dated by Sofia's day, not Postgres's

**Did** — the assembly ITs' fixture SQL goes through `sofiaDated(...)` (`SofiaToday.kt`, test code), which writes today in Sofia as a date literal in place of Postgres's `current_date`. That covers 19 inserts and updates across the five assembly ITs: titles, mandates and household members. `current_date ± n` keeps its offset from the day the app asks the policy about. No production code changes.

**Why** — #213: `current_date` is the session's day, UTC in CI. From 21:00 UTC (22:00 in winter) it is a day behind Sofia's, so "a title that begins tomorrow" was already in force by the app's legal day, and `ProxyPersistenceIT` failed every night.

**Rules covered** — PM-SYS-004 (no new test: the existing ITs, made independent of the session's day).

**Verified** — against Postgres 16 under Testcontainers, run locally for the first time: the Docker daemon started with `DOCKER_MIN_API_VERSION=1.24`, the image pulled from `mirror.gcr.io` (Docker Hub answered 429), Ryuk off. With the test JVM's zone at UTC+14 (pgjdbc gives the session the JVM's zone, so `current_date` is a day ahead of Sofia), `AssemblyPersistenceIT` failed before the fix. After it, all 22 assembly ITs pass in UTC+14 and in UTC. The nightly direction (the session's day behind Sofia's) cannot be produced by a zone at this hour. The fix removes the session's day from the fixtures altogether, so both directions are covered.

**Decisions** — none. Mine: a date literal in place of `current_date`, rather than threading parameters through each statement. The SQL stays as it was written, and the day comes from `toSofiaDate`, the one utility.

**Open** — `identity_org/MandateAdministrationIT` (2) and `registry/BookPersistenceIT` (1) still use `current_date`. Both pass with the day a day ahead; neither sits on a policy boundary that I found. They belong to those lanes · `tools/check_legal_today.py` reads main sources only: a gate over test SQL would keep this from returning (tooling) · how to run the ITs on a machine like this one, written in the Verified line above.
