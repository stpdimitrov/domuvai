## WEB-35 · 2026-10-26 · web — a fee sheet uploaded and its column mapping confirmed, on `/entrance/intake`

**Did** — the intake's first web screen (ADR-012 steps 1–3), mode BOTH, linked from the entrance sidebar as "Внасяне на таблица". A no-script form uploads a `.csv`. A server action reads it as UTF-8, drops a leading byte-order mark and asks `POST /api/intake/entrances/{entranceId}/fee-sheet/profile`. The page shows every column the API answered, the mapped ones first in its order, then the ones it could not place. Each column has a select preset to the API's field, or "не се внася". The page names the unplaced columns and the required fields no column carries, as the API lists them. A second form confirms the person's choice per column. The sheet is carried in the form as base64, because a form posts its line breaks as CRLF. The proposal shown beside the confirmed mapping is asked of the API again for the same bytes, never carried back by the form. Nothing is stored, as no API keeps a mapping before the dry-run. The web does not judge the choice: a field chosen twice or a required one left out is for the dry-run (WEB-36) to refuse. A refusal is shown in the API's words. On confirming, the sheet and the choices are kept.

**Rules covered** — PM-SEC-001 (the API decides who may profile, G-1; the web shows its 403). ADR-012 §2 steps 1–3. Intake owns no rule of its own (S-39).

**Tests added** — `tools/check_e2e.py` `intake_screen`, item 14, signed in in CI:

- confirming, with one unplaced column (`м2`) given `BUILT_AREA`, shows it confirmed, and the form keeps the choice;
